# lnwdeck v13.0.0

Release date: 2026-08-12

This release makes the refresh pipeline stable and the desktop window
responsive. Refresh no longer freezes the UI, database commands no longer run
on the main thread, and provider collection now runs concurrently instead of
one provider at a time.

## Changes

- **The window never freezes during refresh.** Every database-touching Tauri
  command (overview, usage history, costs, budgets, alerts, settings,
  providers, sessions, analytics and the settings/session writes) moved off
  the main thread onto the async runtime pool. The refresh cycle no longer
  holds the provider registry lock for its whole duration, so reload bursts
  triggered by per-provider update events cannot block the window.
- **Providers refresh concurrently.** Collection (detect + usage + quota)
  runs on a bounded 4-worker pool; persistence is serialized on the single
  SQLite connection in registry order. A refresh cycle is now bounded by the
  slowest provider batch instead of the sum of all providers.
- **Codex transcripts are parsed once, not every cycle.** The Codex adapter
  previously re-read and re-parsed every session file on every refresh (about
  1.1 GB / 95 files, ~20 seconds, saturating disk and CPU). Parsed records
  are now cached per file keyed by size+mtime: unchanged append-only sessions
  are reused and only new or changed files are read. The usage persist path
  also prepares its INSERT statement once instead of once per event (26k
  prepares for a single Codex batch).
- **Dashboard queries use the timestamp index.** Time-filtered queries
  compared the `timestamp` column through `julianday()`, forcing a full table
  scan on every load. They now compare canonical UTC RFC3339 text directly so
  SQLite can use `idx_usage_timestamp`.
- **Overview costs aggregate in SQL.** The overview cost pass no longer
  streams every `usage_events` row into Rust to re-price it; recorded costs
  and unpriced tokens are aggregated per (provider, model) in SQL and
  estimated once per group.
- **Per-provider updates stream in with debounced reloads.** Refresh events
  update pages incrementally instead of reloading everything at the end, and
  reloads are debounced so a completed cycle causes one refresh, not one per
  provider.
- **Background refresh runs less often.** The background refresh cadence was
  reduced so idle machines are not constantly scanned.
- **A larger SQLite page cache.** SQLite is given a 64 MB page cache, so
  dashboard queries that used to take up to ~4 seconds on a cold page cache
  now complete in hundreds of milliseconds.
- **Lightweight shell status.** The topbar and the persistent application
  shell use new lightweight commands (`get_app_freshness` /
  `get_app_shell_status`) that read only last successful sync time, theme and
  the unacknowledged alert count. They avoid integrity checks, full
  diagnostics scans and alert re-evaluation on every refresh completion.
- **Latest-request guard for page loads.** Pages use a shared guard so only
  the latest refresh result wins when multiple cycles overlap, preventing
  older results from overwriting newer ones after a slow cycle.

## Privacy

- No prompts, responses, source code, file contents, file names, absolute
  paths or secrets are stored, and none are touched by this release.
- Credential, quota and usage behavior is unchanged from v12.0.1; the Codex
  transcript cache is in-memory only and never persisted.
- Network, credential and hook behavior is unchanged.

## Installing

1. Close lnwdeck from the tray menu.
2. Install the v13.0.0 installer over the existing installation, or use the
   portable build.
3. Start lnwdeck and refresh providers.
