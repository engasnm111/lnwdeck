# lnwdeck v0.2.0

lnwdeck v0.2.0 introduces a normalized quota pipeline and a Windows floating usage widget, replacing placeholder data with real provider status. All metadata stays on your machine: no cloud accounts, no sync.

## Highlights

- Normalized multi-window quota reporting end to end: domain model, SQLite storage, independent refresh channel, dashboard read model, and a `quota-updated` event
- Windows floating widget with per-provider remaining-quota bars, reset countdowns, and honest stale/error/auth states
- Real passive local collectors for OpenCode, Claude Code, and Codex CLI (usage-window estimates), and Local / Unlimited status for Ollama
- Removed production mock fallbacks that previously hid backend failures
- Per-provider refresh so one adapter can be re-scanned without touching the rest
- Provider contract suite enforcing the standardized data rules across all ten adapters

## Floating Widget

The widget runs in its own window and shows the quota dashboard read model:

- Provider quota bars and remaining percentage (only when a real limit is known)
- Reset countdown that ticks locally without refetching
- Stale, auth-expired, rate-limited, and error badges with sanitized error codes
- Local / Unlimited label for Ollama and usage estimates for OpenCode, Claude, and Codex
- Always-on-top window with refresh, dashboard, hide, lock, and opacity controls
- Position persisted across restarts and clamped back on screen when the monitor topology changes

## Fixed

- Production UI no longer displays demo data when backend commands fail
- Provider identifiers normalized (OpenCode uses `opencode` everywhere)
- Floating widget routing (dedicated entry instead of an incompatible hash route)
- Widget opacity command now applies the requested value
- Kiro displayed and priced as its own provider instead of Kimi
- Unknown providers no longer charged with OpenAI rates
- Providers page quota summary sourced from real quota reports instead of event counts

## Security and Privacy

- Quota reports are validated by the privacy guard before persistence
- Local collectors open files read-only, respect file count and byte bounds, and aggregate only numeric token counts and timestamps
- No credentials, cookies, prompts, responses, file names, or absolute paths are stored

## Upgrade Notes

- Existing local usage data is preserved; migration 003 (quota tables) runs automatically at startup
- Restart the application after installing the update
- No configuration changes are required
- Quota collectors need the provider's local CLI data: OpenCode `opencode.db`, Claude `~/.claude/projects`, Codex `~/.codex/sessions`, Ollama local API on port 11434

## Known Limitations

- OpenCode usage events are cumulative session snapshots; delta accounting for repeated session updates is not implemented yet
- Costs, Budgets, and Alerts pages remain placeholders and are not functional
- The browser extension and native messaging host are not part of this release
- Database encryption is not implemented; data lives in local SQLite
- Installers carry update signatures but are not Authenticode-signed
- Quota estimates have unknown limits and are marked as estimates in the UI
