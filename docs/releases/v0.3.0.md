# lnwdeck v0.3.0

This release makes the three local providers that previously reported "no
token records" actually collect the data their tools really keep:

- Gemini usage comes from the CLI session transcripts (`~/.gemini/tmp/*/chats/session-*.jsonl`),
  where every model message carries cumulative token counters.
- Cursor usage and quota come from the account API, authenticated with the
  session JWT Cursor itself stores in `state.vscdb` — Cursor never keeps
  per-request token data in the editor state.
- OpenCode Go quota is compared against the published dollar caps
  ($12 / 5h, $30 / week, $60 / month), so the remaining percentage is real.

All metadata stays on your machine except the Cursor requests, which go over
HTTPS to cursor.com with Cursor's own session credential, exactly like the
Cursor client itself. The credential is never stored, logged or shown by
lnwdeck.

## Highlights

- **OpenCode Go quota with real limits.** Windows are derived from the billed
  USD cost of Go turns in the local `message` table against the caps published
  at opencode.ai/docs/go, with real reset times (five hours after the oldest
  billed turn, next Monday, next calendar month). Falls back to usage-only
  token windows when no Go turns are recorded.
- **Gemini reads the real transcripts.** Session transcripts are streamed
  read-only with bounded files, bytes and line sizes; files larger than the
  budget are scanned from the tail so the most recent usage survives. Token
  counters are cumulative, so per-message usage is the delta between
  consecutive messages; the first message establishes the baseline and a
  counter reset (for example after `/clear`) is reported as its own turn.
  Prompts, responses, summaries and paths never leave the source.
- **Cursor account API.** The adapter extracts the JWT Cursor stored in
  `state.vscdb` (`cursorAuth/accessToken`), derives the account id from
  `~/.cursor/cli-config.json` or the JWT `sub` claim, and reads the per-request
  usage CSV (columns resolved by header name, so reordered exports keep
  parsing) and the utilization summary with Plan / Auto / API lanes and the
  billing-cycle reset.

## Fixed

- Gemini: "Gemini CLI data directory has no token records" on machines with
  real usage, because the generic JSON scan looked for a shape the CLI never
  writes. Verified against real transcripts: 1,844 usage events.
- Cursor: "Cursor state store has no token records", because per-request token
  usage is not stored in `state.vscdb`. Verified against a real account: 521
  events and live quota percentages.
- OpenCode: quota could only report usage with an unknown limit; it now shows
  the remaining percentage against the published Go caps.
- A storage test pinned a retry timestamp to a fixed date and failed once the
  clock passed it.

## Known limitations

- OpenCode Go caps are hardcoded from the published pricing and can prove Go
  turns were billed, but not that the account still holds an active
  subscription.
- Gemini's first token-bearing message of a session establishes the baseline
  and is not counted, so a session is undercounted by one message rather than
  overcounted by a cumulative total.
- Cursor quota percentages come from Cursor's published summary; the plan
  limit itself is not reported per window, so no absolute limit is shown.
