# lnwdeck v10.0.0

Release date: 2026-08-08

v10.0.0 is the Token Analytics, Localization and Pet/Widget UX release. It
keeps the existing local database and settings and adds the analytics model and
desktop surfaces without storing prompts, responses, source code, file names,
absolute paths or secrets.

## Highlights

- TokenTracker-style Dashboard with Day, Week, Month, Year, Total and Custom
  calendar ranges, local-time `[start, end)` conversion to UTC, provider filter,
  total/input/output/duration/session summary, provider cards, usage trend,
  activity heatmap and one-row-per-session table with provider breakdown.
- Shared token formatting everywhere: compact uppercase `K/M/B/T` values and
  full ASCII comma grouping from 1,000. Compact values can be toggled with
  click, Enter/Space and Escape and expose the same full value to assistive
  technology.
- Eight bundled pets with migration-safe seeding. Pet Add/Import moved to the
  Pet page and no longer appears as a duplicate Settings section.
- Strict Codex Pets import: exact HTTPS `codex-pets.net`, official page/API
  routes only, local id validation and canonical download construction. The
  entered URL is never fetched directly.
- Complete nine-locale coverage for Main, Widget, Pet, tray popup, native tray,
  notifications, errors, loading/empty states, tooltips and ARIA labels.
- Accessible themed Widget Bars/Rings/Pet dropdown with dark-mode option styling,
  keyboard handling, outside-click close and reduced-motion support.
- Shared non-blocking Refresh All job with coalescing, progress events,
  incremental results, cancellation checks, timeout boundary and partial-data
  preservation. Tray Sync now uses the same job.
- Notifications now has transactional Mark all as read with optimistic UI and
  rollback on failure.
- Main is the only taskbar window. Widget, Pet and Tray use `skip_taskbar`; a
  hidden Main dashboard can be restored from the tray.

## Fixes

- Corrected full token grouping so `999`, `1,000`, `1,234`, `1,234,567`,
  `1.2B` and `10.2T` render according to the v10 contract.
- Fixed dark Widget mode dropdown readability and added fallback option styling.
- Fixed native tray `Sync now` and last-sync labels so they follow the selected
  language immediately.
- Fixed pet default migration so a removed legacy default is not silently
  restored while the two new v10 defaults are added.
- Fixed duplicate pet controls in Settings and added official import feedback on
  the Pet page.
- Fixed background refresh triggering UI stalls by routing Main, System, Widget
  and Tray through one progress-aware job.

## Migration and data preservation

1. Back up the local lnwdeck database before installing, as with every release.
2. Install v10.0.0 over the existing installation or use the portable build.
3. Existing usage history, settings, custom pets, provider credentials and
   user-deleted legacy defaults are preserved.
4. The first run records which legacy defaults were already acknowledged and
   adds only missing v10 defaults. It does not download the bundled defaults.
5. If a user imports a pet, the validated id is used to create the official
   canonical download URL; arbitrary URLs are not persisted or requested.

No reset, destructive seed or cloud migration is performed by this release.

## Supported architectures and artifacts

The release workflow produces these Windows targets:

| Architecture | Installer | Portable |
|---|---|---|
| x64 | `lnwdeck_10.0.0_x64-setup.exe` | `lnwdeck_10.0.0_x64_portable.zip` |
| ARM64 | `lnwdeck_10.0.0_arm64-setup.exe` | `lnwdeck_10.0.0_arm64_portable.zip` |
| x86 compatibility tier | `lnwdeck_10.0.0_x86-setup.exe` | `lnwdeck_10.0.0_x86_portable.zip` |

The architecture suffix is required for portable archives so the three matrix
jobs cannot overwrite each other's release asset.

Minimum supported Windows version: Windows 10 22H2. WebView2 Runtime is
required.

## Install

- **Installer:** download the installer for the machine architecture, verify
  its `.sig` and SHA-256 entry, then run it as the current user.
- **Portable:** download the architecture-specific portable ZIP and its `.sig`,
  verify both before extraction, extract to a user-writable directory and run
  `lnwdeck.exe`.
- The installer and updater do not require a cloud account. Provider credentials
  remain in Windows Credential Manager.

## Update

Tauri updater reads `latest.json`, selects the matching platform entry, checks
the signature against the public key in `apps/desktop/src-tauri/tauri.conf.json`
and installs only a verified artifact. A manual update check is available from
the native tray menu. Keep the current installation until the new version has
started successfully.

## Rollback

1. Close the dashboard; the tray and background collector must also be stopped
   before replacing binaries.
2. Keep the v10 database and settings directory intact.
3. Install the previous signed installer or extract the previous portable
   build into a separate directory.
4. Start the previous version and confirm history/settings are readable.
5. Do not delete the database to solve a UI issue. Report a migration error with
   the sanitized diagnostics export instead.

The v10 schema is intended to preserve prior data. A rollback is still a binary
rollback, not a database reset; test it on a copy when a future migration adds
new released columns.

## Checksums and signatures

`SHA256SUMS` is generated after all release files are flattened and includes the
installers, portable archives, signatures, `latest.json` and release metadata.
The publish job immediately runs:

```text
sha256sum -c SHA256SUMS
```

Every installer and portable archive has a detached `.sig` produced by the
Tauri signing key. A missing signature fails the release job; `latest.json`
must reference the matching installer signature for Windows x64, ARM64 and x86.

## SBOM and provenance

- `lnwdeck-sbom.cdx.json` is a CycloneDX SBOM generated by
  `anchore/sbom-action` in the publish job.
- GitHub Build Provenance is generated with
  `actions/attest-build-provenance@v2` for the flattened release assets.
- Provenance is available from the GitHub Release/attestation UI and is not
  treated as a substitute for the detached artifact signatures or checksums.

## Verification checklist

Before creating the GitHub Release, the workflow must pass:

```powershell
node scripts/check-release-version.mjs v10.0.0
node scripts/verify-release-assets.mjs release-assets v10.0.0
node scripts/generate-release-metadata.mjs release-assets
```

Then verify `SHA256SUMS`, inspect `latest.json` for all three platforms, verify
all six installer/portable signatures, inspect the SBOM and confirm the GitHub
provenance attestation. The repository fixture contract is covered by:

```powershell
node --test scripts/release-metadata.test.mjs
```

This document describes the release workflow and verification contract. A local
checkout does not constitute a published GitHub Release until the tagged
workflow has completed with the configured signing secret and the artifacts
have been checked on GitHub.

## Known limitations

- Provider collectors are synchronous and refresh cancellation is cooperative
  between providers. The shared job has a 60-second deadline, but an already
  running synchronous I/O call cannot be force-killed safely.
- Installers are updater-signed but not Authenticode-signed.
- The local SQLite database is not encrypted at rest.
