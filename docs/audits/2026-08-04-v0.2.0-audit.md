# lnwdeck source audit - 2026-08-04

Scope: full repository audit at commit `f05f604` (branch `main`), verification of every claim
made in `CHANGELOG.md` 0.2.0 and `docs/releases/v0.2.0.md`, plus new findings, followed by the
remediation record for each item.

Method: source code is the only authority. Documentation claims were checked against the code
paths that would have to implement them. Every verdict below carries a `file:line` reference.
Verdicts: CONFIRMED (claim matches code), PARTIAL (claim true only under conditions the docs do
not state), FALSE (code contradicts the claim).

### 1.2 FALSE or overstated claims

| # | Claim (source) | Evidence that contradicts it | Verdict |
|---|---|---|---|
| F1 | "Provider contract suite enforcing the standardized data rules across all ten adapters"; support table lists Gemini/Cursor/Copilot/Grok/Kiro/OpenRouter as "Not supported" | Those adapters return **successful empty batches**, not an unsupported signal: `crates/providers/gemini/src/lib.rs:13-18` returns `Ok(UsageBatch { events: vec![] })`, and `:22-27` reports `AdapterHealthStatus::Healthy` with message "API-based". Identical shape in `cursor`, `copilot`, `grok`, `kiro`, `openrouter`. `crates/application/src/refresh.rs:190-197` therefore records a collector run with an empty `error_code`, i.e. a successful run, and the System page shows the provider as healthy. This is a fabricated success state for providers that collect nothing. | FALSE |
| F2 | "`set_widget_opacity` applies the requested value instead of ignoring it" | `apps/desktop/src-tauri/src/windows.rs:136-143` sets `.widget-root` inline CSS through `WebviewWindow::eval`, but `apps/desktop/src/windows/widget/FloatingWidget.tsx:196-200` renders `style={{ opacity: state.opacity }}` from its own `localStorage`-backed state, so the next React render overwrites the native value. No frontend code invokes `set_widget_opacity` at all. | FALSE |
| F3 | Auto-update is implemented ("add auto-update with tauri-plugin-updater ... and UI notification", "Installers carry update signatures") | Two fabricated layers exist: `apps/desktop/src/update/UpdateView.tsx:21` and `:33` are explicitly *simulated* ("Simulated update check", "Simulated download") and hardcode version `0.2.0`; `crates/application/src/update.rs:100-109` `verify_signature` returns `Ok(true)` for any non-empty signature string, i.e. it verifies nothing, and `crates/application/tests/` asserts against that fake. No end-to-end updater run (build, publish manifest, install over an older version) had been executed. | FALSE |
| F4 | Frontend event-driven features work in the packaged app (update notification banner, `quota-updated` live refresh, widget drag region) | There is no `apps/desktop/src-tauri/capabilities/` directory and the generated `apps/desktop/src-tauri/gen/schemas/capabilities.json` is literally `{}`. Under Tauri v2 the webview receives permissions only from capability files, so `core:event:listen` and `core:window:allow-start-dragging` are denied. `listen("update-available")` (`components/UpdateNotification.tsx:31-49`), `listen("quota-updated")` (`FloatingWidget.tsx:151-160`) and `data-tauri-drag-region` therefore fail at runtime, and each failure is swallowed by an empty `catch`. App-defined `invoke` commands are unaffected (Tauri v2 exempts them), which is why the pages still load - masking the defect. | FALSE |
| F5 | "Quota estimates report usage windows with unknown limits; remaining-percentage is never fabricated" | `crates/domain/src/quota.rs:105-117`: when `limit == 0` (unknown), `used_percent` is 0 and `remaining_percent` is set to `100.0 - 0.0 = 100.0`. The existing test at `:277-289` asserts that fabricated `100.0`. The invariant survives only because `FloatingWidget.tsx:66-77` happens to branch on `window.limit === 0` first; nothing enforces it at the data layer. | PARTIAL (UI honest, data model fabricates) |
| F6 | "add tests" for Windows packaging and privacy E2E | `apps/desktop/src/pages/packaging.test.ts:6-45` declares the expected config as an object literal *inside the test* and asserts against its own literal - it can never fail. `e2e/privacy.spec.ts:8-45` writes strings itself and then asserts those strings do not contain secrets. Neither touches the real config, artifacts, database, or pipeline. | FALSE |
| F7 | README feature claims | `README.md` lists "Kimi (Moonshot)" as a built-in adapter; no such adapter exists (the crate is `crates/providers/kiro`). README states metrics are stored in "an encrypted/local SQLite database"; no encryption exists (`crates/storage/src/lib.rs`), and `docs/releases/v0.2.0.md:70` admits it. Screenshots predate the 0.2.0 UI (captured 2026-08-04 00:32, before the widget/quota commits). README is also emoji-laden, against the project working rules. | FALSE |
